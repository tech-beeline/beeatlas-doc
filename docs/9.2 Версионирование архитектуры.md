## Контекст

Данный раздел описывает подход по ведению модели архитектуру в условиях изменяющихся версий. Мы исходим из того, что у архитектора есть как минимум две версии системы в работе:

- текущая, установленная на боевой среде
- планируемая, та которая находится в активной разработке

## Решаемые задачи

01. Проектирование изменений в архитектуре на основе старой версии архитектуры
02. Подсветка изменений в архитектуре с добавлением комментариев для объяснения команде
03. Формирование переходных архитектур (parallel run/blue green deployment)
04. Анализ новой версии архитектуры на предмет ответов на вопросы (нфт/фт)
05. Внесение одновременных изменений в старую и новую версию

## Концепция версионирования

Для ведения версий архитектурных элементов (контейнеров и компонентов) предлагается использование механизма Тэгирования:

```java
     container “API Gateway” {
           tags “prod_version” “dev_version” 
     }
     container “My Service” {
           tags “dev_version” 
     }
}
```

С помощью tags можно отмечать продуктивную версию (“prod_version”) и версию которая находиться в разработке (“dev_version”)

Такой подход позволит строить диаграммы для двух версий – той которая на продуктивной среде и той которая в разработке (если одновременно в работе более двух версий, то можно добавить еще тэг).

В таком случае диаграммы могут отличаться фильтрами на элементы:

```
# Диаграмма продуктивной версиии
deployment * "PROD" {
   include element.tag==prod_version
   autoLayout
}

# Диаграмма рабочей версии
deployment * "PROD_PLAN" {
   include element.tag==dev_version
   autoLayout
}
```

Аналогичным образом, можно фильтровать и связи  (relationship.tag==dev_version)

## Применимость данного подхода к вариантам использования

|Вариант использования|Применимость|
|---------------------|------------|
|01. Проектирование изменений в архитектуре на основе старой версии архитектуры|Использование тэгов позволяет просто менять тэги рабочей версии на продуктивную для выведенных в прод элементов.|
|02. Подсветка изменений в архитектуре с добавлением комментариев для объяснения команде|Можно использовать встроенные в Structurizr элементы отображения для подсветки диаграмм по нужным тэгам|
|03. Формирование переходных архитектур (parallel run/blue green deployment)|Есть возможность формировать смешанные представления с двумя видами тэгов - старой и новой системы|
|04. Анализ новой версии архитектуры на предмет ответов на вопросы (нфт/фт)|Выполнимость требований можно проверять по диаграммам, отфильтрованным по тэгам новой версии|
|05. Внесение одновременных изменений в старую и новую версию|Поскольку ,общие контейнеры/компоненты остаются в этом случае едиными, то внесение изменений не требует дублирования|
