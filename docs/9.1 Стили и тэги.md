# Руководство по темам Structurizr DSL для Beeline

Темы задают визуальные стили элементов и связей на диаграммах C4. Теги (tags) применяют эти стили к элементам модели и **позволяют подставлять иконки технологий** (изображения) для контейнеров, компонентов и систем.

---

## 1. Файлы тем (без workspace.json)

Все темы лежат в папке **themes/** — по ссылкам ниже можно скачать нужный файл.

| Файл | Назначение |
|------|------------|
| [**beeline_basic.json**](themes/beeline_basic.json) | Базовая тема: формы элементов (Person, Container, Component, ui, database и т.д.), цвета (landscape, external, legacy, tbd), размеры видов (view_l … view_3xl), стили связей. Подключать **всегда**. |
| [**beeline_tr_icons.json**](themes/beeline_tr_icons.json) | Иконки технологий TechRadar (объединённый набор): языки, фреймворки, платформы, данные, Kubernetes и др. Теги добавляют картинки к элементам. |
| [**kubernetes.json**](themes/kubernetes.json) | Иконки ресурсов Kubernetes (k8s_pod, k8s_deploy, k8s_svc, k8s_ns и т.д.). Для диаграмм с K8s. |
| [**tr_programming_languages.json**](themes/tr_programming_languages.json) | Языки программирования (java, python, go, csharp, js, ts и др.) — стили и иконки по TechRadar. |
| [**tr_frameworks_and_tools.json**](themes/tr_frameworks_and_tools.json) | Фреймворки и инструменты (spring, react, angular, jenkins, jira и др.). |
| [**tr_platforms_and_infrastructure.json**](themes/tr_platforms_and_infrastructure.json) | Платформы и инфраструктура (docker, kubernetes, nginx, terraform, linux и др.). |
| [**tr_data_management.json**](themes/tr_data_management.json) | Управление данными (kafka, postgresql, redis, mongodb, kafka и др.). |
| [**tr_auxiliary_techs.json**](themes/tr_auxiliary_techs.json) | Дополнительные технологии (beeline, hadoop, ignite, yarn) для элементов, не входящих в основные разделы TechRadar. |

---

## 2. Подключение тем в workspace

В блоке `views` файла workspace задаются подключаемые темы. **Пример:** [workspace.dsl](themes/workspace.dsl).

```dsl
views {
    # Базовый набор — подключать всегда
    themes  "beeline_basic.json" "beeline_tr_icons.json"

    # Опционально: для отображения по TechRadar (рамки, adoption, КИ) и иконок по разделам
    # themes  "kubernetes.json" "tr_frameworks_and_tools.json" "tr_platforms_and_infrastructure.json" "tr_data_management.json" "tr_programming_languages.json" "tr_auxiliary_techs.json"
}
```

Порядок тем важен: последующие темы дополняют/переопределяют стили предыдущих.

---

## 3. Как теги добавляют изображения технологий

- В темах для элементов задаётся свойство **`icon`** (обычно base64 PNG).
- Когда у элемента в модели указан **tag**, совпадающий с тегом в теме, Structurizr применяет к этому элементу стиль темы, в том числе **иконку**.
- В результате контейнер или компонент отображается с картинкой технологии (например, логотип PostgreSQL, Kafka, React).

**Пример в DSL:**

```dsl
container "Backend API" "REST API на Spring Boot" "springboot" {
    tags "springboot"
}
```

При подключённой теме с тегом `springboot` и полем `icon` элемент получит иконку Spring Boot.

## 6. Примеры использования тегов в модели

### Системы с семантикой и иконкой

```dsl
softwareSystem "IDP" {
    tags "landscape"
}

softwareSystem "Datafort Beeline Cloud" {
    tags "external"
}

softwareSystem "NEW PRODUCT" {
    tags "tbd"
}

softwareSystem "LEGACY PRODUCT" {
    tags "legacy"
}
```

### Контейнеры с иконками технологий

```dsl
container "Backend" "Сервис на Spring Boot" "springboot" {
    tags "springboot"
}

container "DB" "PostgreSQL" "postgresql" {
    tags "database" "postgresql"
}

container "Queue" "Kafka" "kafka" {
    tags "broker" "kafka"
}

container "Web" "SPA на React" "react" {
    tags "ui" "react"
}
```

### Компоненты

```dsl
component "API" "REST API" "rest" {
    tags "rest"
}
```

### Вид с размером

В конфигурации вида можно задать размер через тег (если ваша конфигурация это поддерживает), например **view_xl** или **view_2xl** для больших диаграмм.

## 7. Рекомендации

1. **Всегда подключать** `beeline_basic.json` и при необходимости `beeline_tr_icons.json` для базовых форм и иконок.
2. Дополнительные темы (`kubernetes.json`, `tr_*`) подключать только при необходимости: они задают стили по adoption/КИ и расширяют набор иконок.
3. Для отображения иконки технологии элементу нужно указать **соответствующий тег** (например, `postgresql`, `kafka`, `springboot`). Можно комбинировать с тегами базовой темы: `"database" "postgresql"`.
4. Иконки в темах хранятся в виде base64 в JSON; теги лишь связывают элемент с записью в теме, где задано свойство `icon`.

---

## 8. Краткая справка: теги → изображения

- Тег в модели (например, `tags "postgresql"`) ищется в подключённых темах.
- Если в теме есть элемент с таким же тегом и полем **icon**, элемент на диаграмме получает это изображение.
- Таким образом, **теги напрямую задают, какая картинка технологии показывается** у контейнера или компонента.


# Использование перспектив

Structurizr поддерживает добавление произвольных «перспектив» к элементам и отношениям в модели архитектуры программного обеспечения. Эта концепция является реализацией перспектив, описанных в таких подходах, как Viewpoints и Perspectives (Eoin Woods и Nick Rozanski).

В общем, если у вас есть одна диаграмма архитектуры программного обеспечения, может быть взглянуть на нее с нескольких разных точек зрения, каждая из которых может подчеркивать различные характеристики. В качестве примера можно привести такие аспекты, как безопасность, производительность, масштабируемость, доступность, нормативно-правовое соответствие и т. д., а также право собственности, оценка технического долга и т. д.

После добавления в модель нескольких перспектив вы можете использовать кнопку бинокля для просмотра текущей диаграммы с заданной перспективой.

Пример применение перспектив к component:

```java
component "API" {
    description "Фасад, отвечающий за обработку и маршрутизацию внешних запросов"
    technology "Java Spring"
    tag "java"
    perspectives {
        "api" "Фасад системы, отвечающий за обработку запросов извне"
        "auth" "точка аутентификации клиентов" 
        }
}
```
