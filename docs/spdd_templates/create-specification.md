# Промпт: создание спецификации

```text
Цель: подготовить анализ и план разработки приложения по моделированию бизнес процессов.

Сначала ничего не меняй в коде. Выполни только анализ, предложи план и подготовь содержание для `documentation/prompts/analysis.md`.

Используй:
- documentation/*.md как исходное задание;
- templates/reasons-canvas-template.md как формат structured prompt для reasons-canvas.md;
- templates/cj_prompt.md как промпт для создания CJ;
- templates/adr-template.md как формат для ADR
- templates/workspace.dsl как шаблон архитектуры в нотации Structurizr DSL;

Базовый принцип:
- пока технологии не фиксируем - цель  этого этапа договорится о принципиальном подходе по CJ/модели данных/правила верификации и сопоставления данных от разных ролей/связей процессной модели и архитектуры CJ
- при создании артефактов проверь что они открываются и не содержат ошибок;
- строго придерживайся шаблонов;
- создавай CJ строго согласно prompt cj_prompt.md;

Создай или обнови:
- documentation/prompts/reasons-canvas.md
- documentation/cj/*.bpmn - CJ пользователей
- documentation/adr/*.md - архитектурные решения
- documentation/workspace.dsl - архитектура проекта в нотации Structurizr DS;
- documentation/analysis.md - анализ требований и решений


В анализе укажи:
1. Какие артефакты спецификации нужно создать или уточнить.
2. Какие архитектурные решения нужно зафиксировать в ADR.
3. Какие CJ нужно создать в формате BPMN Camunda 7 XML.
4. Какие доменные сущности и связи уже понятны.
5. Какие части приложения нужно реализовать.
6. Какие тесты должны подтвердить готовность.
7. Какие риски и вопросы нужно обсудить до генерации кода.
8. Какие секции будущего REASONS Canvas требуют ручного уточнения.
9. Уточни у пользователя вопросы по выбираемым технологиям для фронтенда и бэкенда, а так же по технологиям аутентификации

Требования к результату:
- раздели требования на функциональные и нефункциональные;
- каждое требование должно иметь ID;
- каждое требование должно иметь критерий приемки;
- явно укажи, что не входит в первую версию;
- заполни REASONS Canvas на уровне, достаточном для ревью до генерации кода;
- в Operations добавь маленькие проверяемые шаги;
- добавь открытые вопросы, если они влияют на реализацию;
- не добавляй реализацию кода на этом шаге.

После изменений кратко объясни, какие требования и секции REASONS Canvas являются ключевыми для первой итерации.
```
