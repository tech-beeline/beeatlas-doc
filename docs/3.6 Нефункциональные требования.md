#### Назначение

* Целью определения спецификации API для программной системы является создание четкого и стандартизированного интерфейса для взаимодействия между различными компонентами или системами.
* Для гарантии качества работы программных систем необходимо на этапе проектирования зафиксировать перечень интерфейсов и нефункциональных требований, описывающих требования к тому «как» система должна выполнять свои задачи.

#### На какие вопросы должна отвечать

Минимально к системам фиксируются следующие требования по производительности:

* RPS — максимальное количество запросов в секунду.
* Latency — максимально допустимое время задержки на интерфейсе в миллисекундах.
* Error Rate — максимально допустимый процент ошибок при вызове (например, 0.05; 0.5 соответствует половине процента).

#### Артефакт и инструменты

В зависимости от типа API применяются разные стандарты описания:

* REST [Swagger](https://swagger.io/specification/)
* GraphQL [GraphQL Schema](https://graphql.org/learn/schema/)
* gRPC [Protobuf](https://protobuf.dev/programming-guides/proto3/)
  
#### Инструкция

1. Добавьте в модель вашей системы container, который предоставляет внешний интерфейс, для которого фиксируется НФТ. Он должен быть добавлен "внутрь" моделируемой системы. Например:

```java
my_system = softwareSystem "system name"{
   srv1 = container "Service 1" {
   }
}
```
2. Добавьте в контейнер один или несколько компонентов для спецификации API. Компоненты для спецификации API должны содержать набор property:

| имя     | обязательное | значение   |
|---------|--------------|------------|
| type    | да           | api        |
| api_url | да           | url спецификации api доступный для скачивания (yaml/json/proto/wsdl) |
| protocol| да           | Тип протокола, допустимые значения: rest/soap/grpc |
| tc      | нет          | Код technical capability, которую реализует интерфейс. |
| version | нет          | Версия протокола |
| external_name     | нет           | Внешнее имя для ссылки из других проектов, при отсутствии будет сформировано автоматически. Не должно совпадать с именами переменных для контейнеров.  |

Пример:
```java
my_system = softwareSystem "system name"{
   srv1 = container "Service 1" {
    data_interface_rest_yaml = component "data_interface_rest_yaml" {
      properties {
                  type          api
                  api_url       "http://example.server/api_spec/complex.yaml"
                  tc            BC-000308
                  protocol      rest
                  version       1.1
                  external_name ext_data_provider
              }
          }
   }
}
```
3. Добавьте для каждого end-point (операции) информацию о нефункциональных требованиях. При этом для некоторых end-point может быть указана своя техническая возможность (TC)
   
Пример для **REST** со спецификацией OpenAPI (поддерживается json и yaml формат):

```java
component "data_interface_rest_json" {
    properties {
        type          api
        api_url       "http://nginx/complex.json"
        tc            BC-000308
        protocol      rest
        
        "put /pet"              rps=100;latency=10;error_rate=0.5
        "get /pet/findByStatus" rps=10;latency=15;error_rate=0.3;TC=00001
        "post /pet/{petId}"     rps=2;latency=200;error_rate=0.1;TC=BC-000308
    }
}
```

Пример для **SOAP** со спецификацией WSDL:

```java
component "data_interface_soap" {
    properties {
        type          api
        api_url       "http://nginx/complex.wsdl"
        tc            BC-000308
        protocol      soap
        
        ComplexService.getPerson        rps=100;latency=10;error_rate=0.5
        ComplexService.sendPersonList   rps=10;latency=15;error_rate=0.3;TC=BC-000308

    }
}
```

Пример для **gRPC** со спецификацией proto:

```java
component "data_interface_grpc" {
    properties {
        type          api
        api_url       "http://nginx/complex.proto"
        tc            BC-000308
        protocol      grpc

        UserService.ListUsers       rps=100;latency=10;error_rate=0.5
        UserService.GetUser         rps=10;latency=15;error_rate=0.3
    }
}
```
