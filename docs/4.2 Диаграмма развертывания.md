#### Назначение

Основная цель диаграммы развертывания - показать конфигурацию и расположение физических компонентов в системе, включая их связи, зависимости и каналы связи. Она помогает понять, как развертывается программное обеспечение и как оно взаимодействует с аппаратной инфраструктурой.

#### На какие вопросы должна отвечать

* Визуализация конфигураций аппаратного и программного обеспечения: Диаграммы развертывания помогают понять физическую схему системы, включая серверы, базы данных, сетевые устройства и другие аппаратные компоненты. Она показывает, как эти компоненты связаны между собой и как на них развернуты программные компоненты.
* Выявление зависимостей и каналов связи: Диаграммы развертывания отображают взаимосвязи между программными компонентами и аппаратными узлами. Они показывают, как компоненты взаимодействуют друг с другом и с внешними системами, что помогает выявить зависимости и каналы связи.
* Анализ доступности и отказоустойчивости: Визуализируя распределение программных компонентов по аппаратным узлам, диаграммы развертывания могут помочь в анализе производительности и масштабируемости системы. Это позволяет выявить потенциальные точки отказа и «узкие места»  или области, где могут потребоваться дополнительные ресурсы. Также эта диаграмма является основой для построения crash-тестовой модели

!!! info "Чек-лист самопроверки"

    - [ ] Диаграмма должна быть создана в нотации С4 [Deployment view](https://docs.structurizr.com/dsl/language#deployment-view)
    - [ ] Для каждой среды должна быть создана отдельная диаграмма
    - [ ] На диаграмме должны быть указанны инстансы контейнеров системы (**containerInstance**) ассоциированные с экземпларами контейнеров системы
    - [ ] Для **deploymentNode** должны выполняться правила именования и правила заполнения properties (см. ниже)
    - [ ] Имя **deploymentEnvironment** должно совпадать с именем экземпляра приложения в CMDB

#### Виды Deployment Node

| Элемент развертывания | Правило именования                                                                                                                 |
|-----------------------|------------------------------------------------------------------------------------------------------------------------------------|
|Макросегмент| DMZ STD OPS,DMZ STD RND,PROTECTED STD OPS,PROTECTED STD RND,DMZ NST OPS,DMZ NST RND,PROTECTED NST OPS,PROTECTED NST RND.           
|K8s Namespace| Имя namespace. Например, *EAFDMMART--PROD-YD2235.YD-M35353-K235351*                                                                |
|Pod| Имя pod без HASH версии. Например, для pod *fdm-products-prod-service-6c965988db-zhz9p* название будет *fdm-products-prod-service* |
|VM| Имя виртуальной машины. Например, *yd-seaapp001.eafdmmart-prod.cloud.example.ru*                                                   |
|Database server| Имя сервера базы данных. Например, *fdm-db.database-prod-pg.cloud.example.ru"*                                                     |
|Kafka/Rabbit cluster| Имя кластера. Например *eafdmmart-rmq-prod-1.eafdmmart-prod.cloud.example.ru*                                                      |

# Properties для DeploymentNode и InfrastructureNode

Указывается внутри deploymentNode:

```java
deploymentNode "fdm-db.database-prod-pg.cloud.example.ru" {
    properties {
        "type"                  "vm"
        "flavor"                "cpu2ram8"
        "volume_size"           "50"
        "image"                 "ubuntu-22-04"      
    }
}
```

| Property | Применяемость | Описание | Примеры |
|----------|---------------|----------|---------|
| **type** | Для всех нод, кроме сегмента | Тип узла; если не указан - узел считается "внешним" для приложения | `k8s-cluster` – кластер Kubernetes<br>`k8s-ingress` – ingress в Kubernetes<br>`k8s-ns` – namespace в Kubernetes<br>`s3-region` – регион в хранилище S3<br>`vm` – виртуальный сервер<br>`bare-metal` – физическое оборудование |
| **host** | Нет | FQDN узла; могут быть указаны несколько через запятую. Если указаны, то IP-адреса по ним будут определены при помощи корпоративного DNS и добавлены в соответствующий атрибут | `my_server.cloud.example.ru` |
| **ip** | Для всех нод, кроме сегмента | IP узла; могут быть указаны несколько через запятую, а также в виде подсети | `x.x.x.x`<br>`x.x.x.x/x` |
| **external_ip** | Для нод, доступных из Интернета | Внешний (доступный из Интернета) IP узла; могут быть указаны несколько через запятую, а также в виде подсети | `x.x.x.x`<br>`x.x.x.x/x` |
| **flavour** | Для deploymentNode, кроме:<br>- сегмента<br>- s3-region<br>- k8s-cluster<br>- k8s-ingress<br>- "внешних" для приложения узлов | Значения CPU и RAM, выделенных узлу | `cpu1ram2` |
| **volume_size** | Для deploymentNode, кроме:<br>- сегмента<br>- k8s-cluster<br>- k8s-ingress<br>- "внешних" для приложения узлов | Память, выделенная узлу, в Гб | `100` |

!!! info "Дополнительные параметры для PaaS сервисов"

    Для различных PaaS сервисов могут быть дополнительные параметры. Если вы используете Terraform как средство управления инфраструктурой, то в property type - укажите имя ресурса, а в остальных property - их параметры.
